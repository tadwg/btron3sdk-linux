# bfsk - BTRON ディスクイメージ操作ツール

超漢字V (BTRON3) のディスクイメージを Linux 上で読むためのツールです。
ファイル一覧・レコード構成・レコード内容の表示 / 取り出しと、
ファイルヘッダだけで済む変更 (名前・アクセスモード・日時) ができます。

Python 3 の標準ライブラリのみで動作します。

## 使い方

```bash
python3 tools/bfsk/bfsk.py [-p N | -n FSNAME] IMAGE COMMAND [OPTIONS] [PATH...]
```

コマンドと出力形式は超漢字V の CLI (開発ツール説明書 4.2) に準じています。

| コマンド | 内容 |
|---|---|
| `info` | イメージ形式、パーティション位置、ブート領域長、ブロック長などの詳細 |
| `df` | ディスク状態 (全体 / 空き容量、使用率、ブロック長、最大ファイル数、名前) |
| `ls [-f][-F][-l\|-t] [PATH..]` | ファイルの直下 (リンク先) の一覧。`-f` はファイル自体、`-F` はリンクを含むと `/`・多重参照は `#` を付加、`-l` は詳細、`-t` は日時 |
| `fs [-l] [PATH..]` | レコード構成 (`番号: タイプ サブタイプ : サイズ` / リンクは参照先名)。`-l` でリンクのファイル ID と属性 1〜5、データの配置ブロック |
| `stat [PATH..]` | ファイルヘッダの詳細 (ファイル ID、日時、インデックス開始位置、フラグメント) |
| `check [-v]` | 整合性チェック (fsck 相当、読み取りのみ)。問題があれば終了コード 1 |
| `ren PATH NAME` | ファイル名の変更 (短縮名テーブルも更新)。半角英数記号は全角で保存 |
| `chmod [-o#][-g#][-p#][-a#] PATH..` | アクセスモード / 属性の変更。オプション無しは表示のみ。`-o` 所有者 RWE (0〜7)、`-g`/`-p` グループ / 一般アクセスレベル (0x0RWE)、`-a` 1/2 書込不可 セット/リセット、3/4 削除不可 セット/リセット |
| `chtime [-l D][-a D][-m D] PATH..` | 保存期限 / アクセス日時 / 更新日時の設定 (D は `年.月.日.時.分.秒`、年は西暦下2桁または4桁)。オプション無しは表示のみ |
| `touch PATH..` | 更新日時とアクセス日時を現在に (既存ファイルのみ) |
| `tp [-r#][-a\|-x\|-b][-e] PATH` | レコード内容 (既定はレコード 0)。オプション無しは生データを標準出力へ出すので、リダイレクトして保存する |

### 共通オプション

| オプション | 内容 |
|---|---|
| `-p N` | MBR のパーティション番号 (1-4)。省略時は自動検出 |
| `-n FSNAME` | ファイルシステム名で選択 (例: `-n B-right/V`)。CLI の `/SYS` のようなディスク指定に相当 |
| `-i` (各コマンド) | PATH の代わりにファイル ID で指定 (例: `fs -i 83`) |

### パスの書き方

- ルートファイルから、リンクレコードをたどった名前を `/` で区切って指定します (`/` で始めなくても同じ)。`.` と `..` も使えます
- 全角 / 半角は区別しません (`STARTUP.CMD` で `ＳＴＡＲＴＵＰ．ＣＭＤ` に一致)
- 同じ名前のリンクが複数あるときは、2 つ目以降を `名前:1`、`名前:2` … で指定します (`ls` もこの形で表示)
- `*` はワイルドカード。`%` は次の 1 文字をそのまま扱います (`%*`、`%:`、`%/`、`%%`)

### 例

```
$ bfsk.py a.vmdk ls -l /
ATYPE ATR   NREC  NLNK  NREF       SIZE    BLK  MTIME                NAME
0003  H----     1     0     1      31936      2  2024-02-13 06:21:11  ＳＢＯＯＴ
0003  H----     1     0     1     251672      9  2024-02-13 06:21:11  ＢＴＲＯＮ．ＳＹＳ
...

$ bfsk.py a.vmdk fs -l -i 83
  0:  8 0000 : 142  [blk 2432 ofs 0]
  1:  8 0000 : 114  [blk 2432 ofs 146]
  2: 0 0000 :   951 [004e 0000 8000 0003 8000] : 超漢字Ｖ早分かり
...

$ bfsk.py a.vmdk tp -a STARTUP.CMD | head -3
*

*

$ bfsk.py a.vmdk tp BTRON.SYS > btron.sys      # レコード 0 をファイルに保存
$ bfsk.py a.vmdk tp -r 11 -x -i 83 | head       # 16 進ダンプ
```

### 整合性チェック (check)

次を検査します。エラー (`ERROR`) は不整合、警告 (`WARN`) は害の少ない状態 (どこからも使われていない使用中ブロックなど) です。

- システムヘッダ: ブロック長、ビットマップの大きさ、空きブロック数とビットマップの未使用数
- ファイル ID テーブル: 各ファイルヘッダの開始 / 終了 ID とヘッダ内ファイル ID、短縮名テーブルの値
- 各ファイル: 総レコード数、リンク数、総バイト数、総使用ブロック数 (重複を除いた実数)
- ブロック内のレコード配置: 重なり、区切りコード (4.3.8)、フラグメントテーブルと実際の空き領域
- 参照カウント: ファイル ID テーブルの値とリンクレコードの実数 (ルートは +1)
- ブロックの所有: 2 つのファイルによる二重使用、ビットマップとの食い違い、不良ブロック
- ルートから到達できないファイル

サンプルイメージ (40GB, 2528 ファイル, 使用 20670 ブロック) ではエラー・警告とも 0 件です。

### 書き込みについて

`ren` / `chmod` (変更時) / `chtime` (変更時) / `touch` はイメージを直接書き換えます。**作業前にイメージのコピーを取ってください。**
変更するのはファイルヘッダ (と `ren` の短縮名テーブル) だけで、ブロックの割り当ては変わりません。
VMDK / VDI は割り当て済みの領域だけを上書きします。仮想マシンが動作中のイメージや、
スナップショット (差分ディスク) の親になっているイメージには書き込まないでください。

`ren` と `chmod` はファイル管理情報の更新として最新アクセス日時を現在にします (1.6.6)。
`chmod -n` (所有グループ) と、ルートファイル (ファイルシステム名) の `ren` には未対応です。
日時の表示・指定はローカル時刻 (環境変数 `TZ` に従う) です。

`ls -l` の ATR は CLI と同じく `H` 隠蔽仮身、`P` 削除不可、`R` 書込不可、`1`/`2` アプリケーション属性です。
`H` はファイルではなくリンク (仮身) 側の属性で、属性データ1 の 0x8000 です (実身/仮身マネージャ 3.8.3.1 図123)。
`-i` でファイル ID を指定した場合はたどったリンクが無いため `H` は表示されません。

`tp` は端末に直接生データを出そうとするとエラーにします (リダイレクトするか `-a` / `-x` / `-b` を指定)。
複数ブロックにまたがるレコードは連結して出力します。

## 対応形式

### イメージ形式 (ファイル内容から自動判別)

| 形式 | 対応範囲 |
|---|---|
| raw | ディスク全体 (MBR)、パーティション単体 |
| VMDK | monolithicSparse (非圧縮) |
| VDI | dynamic / fixed |

以下は誤読を避けるため、未対応である旨のエラーになります:
圧縮 VMDK (streamOptimized)、記述子ファイル形式の VMDK (flat / 分割)、差分 VDI、qcow2、VHD。
これらは `qemu-img convert -O raw` で raw に変換すれば読めます。

### ディスク構成

- MBR パーティション (タイプ 0x13) を自動検出。パーティション単体のイメージにも対応
- ブート領域の大きさを自動検出 (論理ブロック 1 はブート領域の直後から始まる)

### ファイルシステム

- 準標準フロッピーディスク形式 (リトルエンディアン) のみ対応。
  TRON 標準形式 (ビッグエンディアン) は未対応
- 標準 / 拡張形式1 / 拡張形式2 (ディスク形式 ID 0x6400 / 0x6401 / 0x6402)

## 確認済みの内容

超漢字V の 40GB HD イメージ (raw / VMDK / VDI) で次を確認しています。

- 全 2528 ファイルについて、レコード数・リンク数・総バイト数がファイルヘッダの値と一致
- 全ファイルがルートからリンクでたどれ、全 8661 パス (同名 2750 件を含む) が元のファイルに解決できる
- 全 7226 データレコードがレコードサイズどおりに読み出せる

| 項目 | サンプルでの値 |
|---|---|
| パーティション | MBR 1 番、タイプ 0x13、LBA 63 から |
| ブート領域 | 4096 バイト |
| ディスク ID / 形式 ID | 0x52FE / 0x6402 (拡張形式2) |
| 論理ブロック長 | 32768 バイト |
| 最大ファイル数 | 65535 |

### 仕様書から補足した点

- ファイル ID テーブルのエントリは 32 ビット値として読み、下位 24 ビットが開始ブロック、上位 8 ビットが参照カウント
- 拡張形式2 では、ファイルヘッダ +176 の `ridxofs` がレコードインデックスの開始位置を示す。
  フラグメントテーブルは 8 バイト (サイズ, ブロック内オフセット, ブロック番号) × 可変個
- レコードインデックスは `ridxofs` からブロック末尾までの配列。サンプルでは末尾側に詰めて置かれ、手前は未使用 (0) で埋まる
- ブロック内のレコードの間には 2 バイトの区切りコードが 2 つ入る (4.3.8)。例: 142 バイトのレコードの次は 146 から
- ファイル短縮名は、ファイル名を 2 文字 (各 16 ビット) ずつ 32 ビットにまとめて仕様の手順で計算した値と一致

## 未確認・未対応

- インデックスレベル 1 以上のファイル (間接インデックス): 実装済みだがサンプルに無く未検証
- リンクファイル (ファイルタイプ 0): サンプルに無く未検証
- 準標準形式の実フロッピーイメージ
- ブロックの割り当てを伴う書き込み (ファイル作成・削除・複製、レコード追加など)
