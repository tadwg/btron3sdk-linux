# bfsk - BTRON ディスクイメージ操作ツール

超漢字V (BTRON3) のディスクイメージを Linux 上で読むためのツールです。
現在は読み取り専用で、ファイルシステム情報とファイルのレコード一覧を表示できます。

Python 3 の標準ライブラリのみで動作します。

## 使い方

```bash
python3 tools/bfsk/bfsk.py [-p N] IMAGE info
python3 tools/bfsk/bfsk.py [-p N] IMAGE records FILEID
```

| コマンド | 内容 |
|---|---|
| `info` | イメージ形式、パーティション位置、ブート領域長、ブロック長、ブロック数、ファイルシステム名などを表示 |
| `records FILEID` | 指定したファイル ID のファイルヘッダ情報、フラグメントテーブル、レコード一覧を表示 |

`-p N` で MBR のパーティション番号 (1-4) を指定できます。省略時は自動検出します。

### 出力例

```
$ python3 tools/bfsk/bfsk.py a.vmdk records 83
file id   : 83 (header block 2431, ref 1)
name      : 超漢字サンプル集
type/attr : 1 / 0x000   apptype 0x1002
level     : 0   records 12   links 9   bytes 48356   blocks 3
created   : 2024-02-13 06:29:17   updated 2024-02-13 06:36:24
index ofs : 6336   fragments: 17170@12351+15598

  no kind type subtype       size offset  blocks / link
   0 data    8     0x0        142      0  2432
   1 data    8     0x0        114    146  2432
   2 link    0     0x0          -      -  -> fid 951 超漢字Ｖ早分かり  attr=004e,0000,8000,0003,8000
  ...
  11 data    1     0x0      48100    264  2432 12351
```

- `data` は通常レコード。`blocks` は使用する論理ブロックで、連続する場合は `開始+個数` で表示
- `link` はリンクレコード。リンク先のファイル ID とファイル名、属性データ 1〜5 を表示
- `fragments` は `サイズ@ブロック+オフセット` の形式

## 対応形式

### イメージ形式 (ファイル内容から自動判別)

| 形式 | 対応範囲 |
|---|---|
| raw | ディスク全体 (MBR)、パーティション単体 |
| VMDK | monolithicSparse (非圧縮) |
| VDI | dynamic / fixed |

以下は誤読を避けるため、未対応である旨のエラーになります:
圧縮 VMDK (streamOptimized)、記述子ファイル形式の VMDK (flat / 分割)、差分 VDI、qcow2、VHD。
これらは `qemu-img convert -O raw` で raw に変換すれば読めます。

### ディスク構成

- MBR パーティション (タイプ 0x13) を自動検出。パーティション単体のイメージにも対応
- ブート領域の大きさを自動検出 (論理ブロック 1 はブート領域の直後から始まる)

### ファイルシステム

- 準標準フロッピーディスク形式 (リトルエンディアン) のみ対応。
  TRON 標準形式 (ビッグエンディアン) は未対応
- 標準 / 拡張形式1 / 拡張形式2 (ディスク形式 ID 0x6400 / 0x6401 / 0x6402)

## 確認済みの内容

超漢字V の 40GB HD イメージ (raw / VMDK / VDI) で、全 2528 ファイルについて
レコード数・リンク数・総バイト数がファイルヘッダの値と一致することを確認しています。

| 項目 | サンプルでの値 |
|---|---|
| パーティション | MBR 1 番、タイプ 0x13、LBA 63 から |
| ブート領域 | 4096 バイト |
| ディスク ID / 形式 ID | 0x52FE / 0x6402 (拡張形式2) |
| 論理ブロック長 | 32768 バイト |
| 最大ファイル数 | 65535 |

### 仕様書から補足した点

- ファイル ID テーブルのエントリは 32 ビット値として読み、下位 24 ビットが開始ブロック、上位 8 ビットが参照カウント
- 拡張形式2 では、ファイルヘッダ +176 の `ridxofs` がレコードインデックスの開始位置を示す。
  フラグメントテーブルは 8 バイト (サイズ, ブロック内オフセット, ブロック番号) × 可変個
- レコードインデックスは `ridxofs` からブロック末尾までの配列。サンプルでは末尾側に詰めて置かれ、手前は未使用 (0) で埋まる
- ファイル短縮名は、ファイル名を 2 文字 (各 16 ビット) ずつ 32 ビットにまとめて仕様の手順で計算した値と一致

## 未確認・未対応

- インデックスレベル 1 以上のファイル (間接インデックス): 実装済みだがサンプルに無く未検証
- リンクファイル (ファイルタイプ 0): サンプルに無く未検証
- 準標準形式の実フロッピーイメージ
- 書き込み
